# Plan: #94 PV inverter data simulator (parent #26)

## Placement decision
`ml/src/solarops_ml/simulator/` (Python), NOT the .NET backend.
- ADR-185 (decision 5 + follow-up issue 3): "Simulator v Pythone (pvlib)", generative core, seed, fault labels in a
  separate `fault_labels` output outside the ingest contract.
- ADR-187: "fault_labels a injektor su modul simulatora, nie API". ADR-178: simulator calibrated on DKASC shape.
- Backend only receives data (#95 ingest). The simulator emits JSON that #95 can POST.
- Dependency note: pvlib is NOT in `ml/pyproject.toml` and we may not add dependencies. The simulator is pure
  numpy/pandas (pandas already depends on numpy): Spencer/NOAA solar position + Meinel-style clear-sky + isotropic
  transposition to the plane of array. If the team wants pvlib later, `solar.py` is the only module to swap.

## Format
ADR-185 telemetry contract `schemaVersion "1.0"`: envelope `{schemaVersion, deviceId, readings[]}` (max 288 per
batch); reading fields `messageId, timestamp (UTC, Z), intervalSeconds=300, status (SunSpec St names), acPowerW,
dcPowerW, acVoltageV, acCurrentA, frequencyHz, powerFactor, temperatureC, strings[{id,voltageV,currentA,powerW}],
energy{dayWh,totalWh}, errorCode`. Night: samples with `SLEEPING` and 0 W. `messageId` = uuid5(deviceId, timestamp),
so output is reproducible. Orientation follows weather "format v2" (`tilt`, `azimuth`; 0 = south, 180 = north; the
plane-of-array irradiance, GTI, drives the model). Default site: `alice_springs` from `ml/config/locations.toml`
(tilt 20, azimuth 180). `dayWh` resets at local midnight (`utc_offset_hours`, default Alice Springs +9.5).

## Signatures
- `solar.solar_position(times, lat, lon) -> DataFrame[zenith_deg, azimuth_deg]` (compass azimuth, N=0, clockwise)
- `solar.clear_sky(zenith_deg, doy) -> (ghi, dni, dhi)`; `solar.plane_irradiance(...) -> gti`
- `SimulatorConfig(device_id, latitude, longitude, tilt, azimuth, capacity_kwp, dc_ac_ratio, utc_offset_hours,
  cloudiness (0..1 mean), seed, string_count)`
- `FaultSpec(type: "power_drop"|"inverter_fault", start, end, severity)`
- `simulate(config, start, end, faults=()) -> SimulationResult(readings: DataFrame, labels: DataFrame)`;
  labels = `expected_power_w, fault_active, fault_type` (outside the ingest payload, ADR-185/187)
- `to_payloads(result, device_id) -> list[dict]` (batches <= 288)
- CLI: `python -m solarops_ml.simulator --location alice_springs --start .. --end .. --seed N [--fault ..] --out f.json`

## Model
Cloud cover = AR(1) process around `cloudiness` (clipped 0..1); clear-sky GTI scaled by `1 - 0.75 c^3.4`
(Kasten-Czeplak). PVWatts-like DC (gamma -0.4 %/K, NOCT cell temperature), inverter eff 0.96 with clipping at
kWp/dc_ac_ratio, 0.5 % multiplicative noise. All random draws happen regardless of faults, so a fault only changes the
output inside its window.

## Tests (`ml/tests/test_simulator.py`, written first)
1. same seed -> identical readings/payloads; different seed -> different.
2. night -> 0 W, SLEEPING.
3. summer noon > winter noon (Kosice north, Alice Springs south); summer day energy >> winter.
4. cloudier -> less energy.
5. power_drop lowers power by ~severity only in window; inverter_fault -> FAULT, 0 W, errorCode != 0; labels mark it.
6. payload shape: 5-min spacing, UTC Z, <= 288 per batch, monotonic totalWh, dayWh reset, field set equals ADR schema.
7. input validation (end <= start, tz-naive, bad severity/type/cloudiness).
